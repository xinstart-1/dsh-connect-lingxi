# 0.0.9：模型展示与官网同步（清单、顺序、倍率、徽标、说明）

> 之前的模型页与选择器只是「上游给什么就显示什么」，和灵犀官网的「内置模型」列表
> 对不上：官网有徽标（`NEW` / `正式版` / `首发接入`）、有模式说明、倍率带 `~`，
> 这些我们一个都没有；兜底表里还留着官网根本没有的 `auto` 与 `V4 Flash`，
> 而官网已经上架的 `Kimi-K3.1 Pro` 我们又缺。

## 三个判断，以及为什么

### 1. 官网没有的模型，兜底表里也不留

`auto`（自动推荐）与 `deepseek-v4-flash-0731` 在官网「内置模型」列表里都不存在。
兜底表只在**未登录或接口读不到**时生效 —— 那种时候用户会拿它和官网对照，
多出来两个官网没有的模型，第一反应是「这插件在瞎编」。宁可少列，不可多列。

反过来，官网有而旧表缺的 `kimi-k3.1-pro` 必须补上：用户登录前看到的选择器里
少了官网明明有的模型，同样是失真。

### 2. 倍率的 `~` 照抄，不要自己算

官网写 `~0.12x`，旧表写成 `0.12x`。`~` 表示「约等于 / 折扣价」，
去掉它就是**把不确定的事实说成确定的事实**。这类字段一律照抄上游原文。

### 3. 徽标只透传，不发明

`badgeTone` 只做语气映射（`正式版`→success、`NEW`/`首发接入`→info），
**不改文案**。上游以后加一个新的徽标文案，会以 `neutral` 灰色显示出来 ——
我们不知道它的含义，用中性色比猜一个颜色诚实。

徽标文案本身来自两处：登录后用上游 `/sessions/plans` 给的；未登录用兜底表里
照抄官网的那份。

## 一个顺带修掉的测试缺陷

`test/apply.test.ts` 之前没有关掉 `autoDetectCookie`，于是**每个用例都会真的去扫
本机浏览器 cookie 库**（Edge 开着时还要先做快照）。表现是整份测试偶发卡死几十秒、
且在别人的机器上行为不同。现在显式传 `autoDetectCookie: false`，并把用例超时放宽
到 30 秒（真机上探测本身可能就慢）。

同时修掉一条过期断言：它写死「静态表第一条不支持图片」，而第一条现在是
DeepSeek V4.1 Flash（官网标了图片能力）。改成跟着静态表走，官网换顺序时这条
不会变成误报。

## 怎么确认

重启 DSH 后打开模型选择器：

- 顺序与官网一致，`DeepSeek V4.1 Flash` 带 `NEW`、`DeepSeek V4 Pro` 带 `正式版`
- `GLM-5.3` / `GLM-5.3-Flash` 带 `首发接入`
- 列表里**没有**「自动推荐」和「DeepSeek V4 Flash」
- 有 `Kimi-K3.1 Pro`

插件卡片「模型」页应当显示同样的徽标，Pro / Max 模式下面多一行说明。
