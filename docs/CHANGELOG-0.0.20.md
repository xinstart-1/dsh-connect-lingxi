# 0.0.20：新会话里不再冒出智点读数（并照 WorkBuddy 换皮肤）

这一版修两件事：**新会话/没选灵犀模型时不再显示智点读数**，以及把读数的皮肤
换成 WorkBuddy 那种「纯文字、无边框」的写法。

## 症状

新开一个会话、还没选模型时，输入框左侧已经出现
`WPS灵犀 · 3,100 智点`；同一行里还并排着别的连接器（raccoon 的「小浣 · 7,858 积分」等）
的读数。选了别家 provider 的模型时，灵犀的余额同样照常显示。

## 根因

- 0.0.17 把门控从「藏起来」改成「读不到投影就照常显示」（fail-open），本意是修
  「重启后胶囊消失」。副作用：新会话的 `modelSelection` 是 `null` /
  `next`、`lastUsed` 都没有（provider 未知）时也显示 —— 而「不知道用哪家模型」
  被当成了「用灵犀」。
- 同一格上 WorkBuddy 的做法是严格门控：选中 provider 不是自己就返回 `null`，
  新会话自然不显示。两相对照，本插件的规则是错的。

## 这一版做了什么

- **门控收紧成 WorkBuddy 规则**：只有 `provider === 'wps-lingxi'` 才渲染读数；
  provider 未知（新会话）或属于别的连接器都不渲染。
- **保留唯一的 fail-open 场景**：读投影**抛异常**（宿主改了投影名/不在会话作用域）
  时上报 `gate-error` 后照常显示 —— 那说明宿主接口变了，不是「没选模型」，
  不该再回到「重启后胶囊消失」。
- **皮肤照 WorkBuddy**：纯文字、无边框、无底色，悬停才浮一层浅底；
  `12px/18px`、弱化色（`--dsw-alias-label-tertiary`）、数字等宽（`tabular-nums`）、
  `padding:2px 6px`、`border-radius:6px`（类名 `.dsm-lingxi-pill-trigger`）。
- **文案形状照它**：`WPS灵犀 · 3,100`（产品名 + 数字，不在胶囊上堆「智点」）。
  单位挪到 tooltip 与弹层账号表里。
- 测试：新会话（`next`/`lastUsed` 为 `null`）、没有投影、别的 provider 三种情况
  都必须返回 `null`；读投影抛异常时仍要渲染；并断言 CSS 契约（无边框、悬停反馈、
  `tabular-nums`、`12px/18px`）与文案形状。

## 与历史规则的关系

0.0.1 / 0.0.17 文档里的「宿主没给投影就照常显示，『我不知道』不等于『藏起来』」
被这一版收窄：**只有「读不到（异常）」才照常显示**；「读到了、但没选模型」属于
「确实不该显示」。
