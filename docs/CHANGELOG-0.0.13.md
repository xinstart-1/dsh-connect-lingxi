> 上一版账号池只在有 2 个以上账号时才显示，所以你只有一个账号时**整块看不见**，
> 页面上只剩「忘记登录态」。这是设计错误：WorkBuddy 的账号池是常驻显示的。

## 关键设计决定

### 1. 勾选框与「切换账号」必须是两个独立控件

上一版整行可点 = 切换账号。加上勾选框之后，**点勾选会顺带把账号切了**。
现在：勾选框只改 `enabledAccounts`，切换是行尾一个独立按钮，且当前账号没有这个按钮
（点了没有意义）。

### 2. 勾选名单为空 ≠ 全选

用户取消勾选全部之后，如果实现把空名单当「全选」，结果就是「全都没勾，反而全被启用」——
这是最容易被当成 bug 的行为。所以空名单的语义是**一个都没有**，
`pickAccount` 直接返回「没有勾选任何账号」。

### 3. 余额读不到 ≠ 0

`undefined` 表示没查到（未登录 / 接口失败 / 还没拉过），界面显示 `—`；
`0` 表示真的没钱。把两者混为一谈会让用户以为账号被扣空了。
测试 `账号池：余额读不到显示破折号，不是 0` 钉住这一点。

### 4. 只在勾选的账号上花网络请求

每个账号一次余额请求，池里十个账号就是十次。没勾的账号只留在列表里备查，
不去拉它的余额 —— 用户没说要管它。

### 5. 余额缓存放内存，不落盘

余额是「此刻」的事实。落盘后下次启动会先显示过期数字，用户会以为那是真的。
内存缓存 + 每次打开卡片重拉，比「先显示旧数字再纠正」诚实。

### 6. 批量签到不切换当前账号

`claimFor` 用那个账号自己的 cookie 直接走签到流程，不调用 `switch-account`。
批量签到不该改变「我现在在用哪个」。

## 挑账号的规则（`src/host/pool.ts`，12 条单测钉住）

1. 池开关关着 → 永远用「当前选用」那个，余额再高也不看别的
2. 池开关开着 → 只在勾选的账号里挑，余额高的优先
3. 勾选名单空 → 什么都不挑（不把空当全选）
4. 余额读不到不算 0 → 仍留在候选里，但排在已知余额之后（一次网络抖动不该
   把好账号踢出池子）
5. 当前选用的账号已不存在 → 不静默换人，返回「未登录」让上层处理
6. 全部余额未知 → 按原顺序取第一个（同样输入必须给同样答案，不随机）

## 新增动作

| 动作 | 作用 | 会不会花智点 |
| --- | --- | --- |
| `claim-pool-checkin` | 给勾选的账号逐个签到 | 否（签到是领，不是花） |
| `test-pool-accounts` | 逐个测勾选账号能否对话 | **是**（每个账号一次最小对话） |

测试用 `openChat` 发一次 `ping`（maxTokens 8），只看有没有 SSE 数据回来。
为什么不只查余额：余额接口 200 不代表对话通道可用。

## 没做的（明确说明）

1. **设备头虚拟/真实**：设置项存了（`deviceHeaderMode`，默认 `virtual`），
   但**还没有真正作用于请求头**。给每个账号派生独立设备指纹需要在
   `KSO_PARTS` 那条链路上做，我还没验证过灵犀是否按设备限流、
   改了会不会反而被判异常 —— 没验证就改请求头，风险比收益大。
   所以这一版只把设置项存下来，界面上先不暴露开关。
2. **自动签到**（WorkBuddy 的「每天自动签到」）：`autoCheckin` 字段早就有，
   但账号池的批量自动签到需要「哪天签过」的跨账号记录，这一版没做。
